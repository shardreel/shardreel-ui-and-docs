<Callout type="info" title="Supported platforms">
Apple Silicon Macs, and Linux (Debian or Ubuntu), including Windows through WSL2. Intel Macs are not supported. Check the [hardware and storage requirements](/docs/requirements) first. shardreel refuses to start a job below the disk or RAM minimum.
</Callout>

shardreel is open source. You run it from a local clone of the repository: [github.com/shardreel/clipforge](https://github.com/shardreel/clipforge).

## Requirements

| Tool | Why it is needed |
| --- | --- |
| Rust toolchain | Builds the backend |
| bun | Builds the web UI |
| cmake | Builds whisper.cpp, which the Whisper bindings compile |
| ffmpeg with libass | Decoding, filters, encoding, and burned-in captions |
| yt-dlp | Downloading videos from URLs |

<Steps>
<Step>

### Install the command-line tools

<Tabs items={['macOS', 'Linux', 'Windows (WSL2)']}>
<Tab value="macOS">

```bash
brew install cmake yt-dlp ffmpeg-full
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
curl -fsSL https://bun.sh/install | bash
```

`ffmpeg-full` is a keg-only build that includes libass. It does not replace an ffmpeg you already have. shardreel looks for it in `/opt/homebrew/opt/ffmpeg-full/bin` first and falls back to your `PATH`.

</Tab>
<Tab value="Linux">

```bash
sudo apt install build-essential cmake pkg-config libclang-dev ffmpeg pipx
pipx install yt-dlp
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
curl -fsSL https://bun.sh/install | bash
```

Transcription runs on the CPU by default. With an NVIDIA GPU and the CUDA toolkit, build with `cargo run --release --features cuda`. See [Linux and WSL2](/docs/guides/linux-and-wsl).

</Tab>
<Tab value="Windows (WSL2)">

Install WSL2 with an Ubuntu distro, open its terminal and follow the Linux steps inside it. Keep the project on the Linux filesystem, not under `/mnt/c`. See [Linux and WSL2](/docs/guides/linux-and-wsl).

</Tab>
</Tabs>

</Step>
<Step>

### Clone the repository

```bash
git clone https://github.com/shardreel/clipforge.git
cd clipforge
```

To pin a release instead of the latest `main`, run `git tag` and `git checkout <tag>`.

</Step>
<Step>

### Build the web UI

```bash
cd web
bun install
bun run build
```

</Step>
<Step>

### Run the app

```bash
cargo run --release
```

The first build compiles whisper.cpp and takes a few minutes. When it is ready, the server prints its address:

```txt
clipforge listening on http://127.0.0.1:8787
```

</Step>
<Step>

### Check the setup

Open `http://127.0.0.1:8787` and go to **Settings**. The System card shows your platform, the disk, memory and CPU checks, and each tool as OK or Missing, with the command that fixes it.

</Step>
</Steps>

## Run your first job

1. Open **New job**.
2. Drop in a video, or switch to **Path or URL** and paste a path or a YouTube or Twitch link.
3. Leave the defaults and press **Generate clips**.
4. Watch the stages on the job page. When it finishes, play the clips in the grid.

The first job with speech recognition downloads the Whisper model, about 1.6 GB for the default `large-v3-turbo`, into `~/.clipforge/models`. Later runs reuse it.

Clips are saved to `~/Movies/clipforge/` on a Mac and `~/Videos/clipforge/` on Linux and WSL2 by default, in a folder named after the video. Change the output folder per job.

## Update to the latest version

```bash
cd clipforge
git pull
cd web && bun install && bun run build && cd ..
cargo run --release
```

Your settings, models and cache live in `~/.clipforge`, so updating does not touch them.

## Develop the UI

Run the backend and the Vite dev server side by side:

```bash
cargo run --release
cd web && bun run dev
```

Open `http://localhost:5173`. Vite proxies `/api` to the backend on port 8787.

## Contribute

shardreel is MIT licensed. Found a bug or want a feature? Read the [contributing guide](https://github.com/shardreel/clipforge/blob/main/CONTRIBUTING.md), then [open an issue](https://github.com/shardreel/clipforge/issues) or send a pull request. To report a vulnerability, follow the [security policy](https://github.com/shardreel/clipforge/blob/main/SECURITY.md) instead of opening a public issue. Fork the repo, create a branch, run `cargo run --release` and `cd web && bun run dev` to test your change, then open a PR against `main`. If something fails during setup, check [Troubleshooting](/docs/troubleshooting) first.
